有了核心 SNP 集，接下来就是拿它和表型做关联。这篇用 fastlmmc 的混合线性模型走一遍，从表型文件重排、亲缘矩阵和群体结构校正，到 14 个性状的 Manhattan 图和 QQ 图，性状换成自己的即可。

有了基因型矩阵和表型，问题就变成哪个位点与性状相关。植物群体里做 GWAS 的主要障碍是群体结构和亲缘关系。群体结构指样本来自不同亚群，等位基因频率本身就有系统性差异；亲缘关系指个体之间的血缘联系，包括家系和更远的共同祖先，描述的是个体对之间的相似程度。如果材料来自不同地理群体，或者本身就是一套育种群体，两个本来无关的位点和性状会因为共同祖先而相关，做出来的结果是整条染色体都是显著信号，这就是 QQ 图整体上翘的来源。所以流程的主体是先把亲缘和群体结构量化出来，作为随机效应和固定效应放进模型扣掉，剩下的才是关联信号。把亲缘关系放随机效应、群体结构放固定效应，这种做法就叫混合线性模型，也就是 LMM，现在是 GWAS 的主流。

## 表型文件

这一步出错不会报错，但会让整个 GWAS 结果作废。先看源表型文件本身合不合格，再按基因型的 .fam 重排一份给 fastlmmc 用的副本（下面第二段用到下一步生成的 .fam，把格式转换做完再回来跑）。

- fastlmmc 的表型文件要求无表头，FID、IID 后接各列性状，顺序与基因型 .fam 完全一致，它是按行对应的。
- 缺失表型写 `-9`。fastlmmc 不认 `NA`，只接受 `0`、`1`、`-9` 或浮点数，写 `NA` 会直接报 `Expected phenotype indicator ... to be 0, 1, -9, or a floating point number`。
- 分类性状不要直接当连续变量。等级性状用线性模型会假设等级之间等距，需要先确认这个假设是否可接受，或者改用相应的模型。
- 检查性状分布是否近似正态。树高、胸径这类量常右偏，偏度很大时先做对数转换，否则关联信号被少数极端个体主导。

先看一眼源表型文件的表头和列数，

```bash
head -1 phenotype_191.phen
```

- 这个文件共 191 个个体、14 个性状，列名依次是 `PH DBH LCD SCD HUB DS NC DWT V WD LC CC HC FL`，前两列是 FID 和 IID。

先确认列数，后面按列号取性状才不会数错：

```bash
awk -F'\t' '{print NF}' phenotype_191.phen | sort -u
```

- `sort -u` 之后只应该有一个数字。列数不一致时有些工具不会报错，只会静默对错表型。

表型文件与 .fam 的样本不一定完全重合，这里表型有 191 个个体，核心 SNP 集只剩 160 个样本，要按 .fam 的顺序重建一份给 fastlmmc 用的表型表，

```bash
awk -F'\t' 'BEGIN{OFS="\t"}
  NR==FNR { if(FNR>1) p[$2]=$0; next }
  {
    split($0, f, /[ \t]+/)
    if(f[2] in p) print p[f[2]]
    else { s=f[1] OFS f[2]; for(i=1;i<=14;i++) s=s OFS "-9"; print s }
  }' phenotype_191.phen 06.gwas/fastlmm/mt160.fam > 06.gwas/fastlmm/pheno_fastlmm.txt
```

- `p[$2]=$0`，表型表按 IID 建索引。不能按行号对，两个文件的个体集合不同。
- `split($0, f, /[ \t]+/)`，.fam 用空格分隔，表型文件用制表符，这里两种都当分隔符，不然在 .fam 上取不到 IID。
- `f[2] in p` 与 `print p[f[2]]`，按 .fam 的样本顺序输出，这样 fastlmmc 取第 N 列就是第 N 个样本。
- `else` 分支把 .fam 里有、表型里没有的个体补成一行 `-9` 缺失，行号不能错位，宁缺勿乱。
- 不用 `-9` 的另一个后果是 fastlmmc 会把空白当 0，当成一个正常的表型值参与回归。

性状与 `-mpheno` 列号的对应关系也顺手生成一份，后面按号索引，

```bash
awk -F'\t' 'NR==1{for(i=3;i<=NF;i++) printf "%d\t%s\n", i-2, $i}' phenotype_191.phen > 06.gwas/fastlmm/traits.txt
```

- `i-2`，列号从 1 开始数，FID 和 IID 不计入。`PH` 是 1，`FL` 是 14。

生成完看一眼，列号和性状名对不上就等于白跑：

```bash
cat 06.gwas/fastlmm/traits.txt
```

- 这份对照表按列号索引时直接用，免得每次翻源文件数第几列。

## PLINK 格式转换

先把 VCF 转成 PLINK 的二进制格式，后面 fastlmmc 和 GEMMA 都读它：

```bash
plink --vcf 06.gwas/qc/05.core.snp.vcf.gz --double-id --allow-extra-chr --vcf-half-call m --set-missing-var-ids '@C#' --memory 22000 --make-bed --out 06.gwas/fastlmm/mt160
```

- `--double-id`，把 VCF 的样本名同时当作 FID 和 IID。与表型文件的写法保持一致，否则合并时对不上样本。
- `--allow-extra-chr`，允许 chr1 到 chr12 这类非人类染色体的写法。不加这个参数，非标准染色体名会被拒绝。
- `--vcf-half-call m`，半缺失的基因型按缺失处理。不加的话遇到半缺失基因型会直接报错。
- `--set-missing-var-ids '@C#'`，把缺失名的位点统一命名成染色体加 C 加位置，例如 chr1C123456。名字必须唯一，否则会被后续按名取值的工具静默覆盖。
- `--memory 22000`，PLINK 可用内存，单位 MB。按可用内存给，太小会退化成频繁读写磁盘。
- 输入是上一步得到的核心 SNP 集，79,455,132 个位点、160 个样本，.bed 约 3.2 GB、.bim 约 2.6 GB，转之前至少留 10 GB 空间。

转换完数一遍行数，样本数和位点数是不是预期的：

```bash
wc -l 06.gwas/fastlmm/mt160.fam 06.gwas/fastlmm/mt160.bim
```

- `fam` 是样本表，`bim` 是位点表，行数就是样本数和位点数。这份数据是 160 个样本、79,455,132 个位点。

数不对就别往下走，写成判断让脚本自己退出：

```bash
[ "$(wc -l < 06.gwas/fastlmm/mt160.fam)" -eq 160 ] || { echo "ERROR: 样本数不是 160"; exit 1; }
```

- 样本数对不上时不要往下跑，fastlmmc 按行对表型，少一个样本整个表型列就错位了。这里写成退出码非零的判断，手工看容易漏。

位点名重复会让按名取值的工具静默覆盖，也用一条判断挡一下：

```bash
[ "$(cut -f2 06.gwas/fastlmm/mt160.bim | sort -u | wc -l)" -eq "$(wc -l < 06.gwas/fastlmm/mt160.bim)" ] || { echo "ERROR: bim 里 SNP 名有重复"; exit 1; }
```

- SNP 名去重后应该与位点总数相等，少了就说明有重名。

再确认坐标没有溢出，越界的位点会算错位置：

```bash
awk '$4<0{print "ERROR: bim 坐标溢出 -> "$0; bad=1} END{exit bad+0}' 06.gwas/fastlmm/mt160.bim
```

- `$4` 是 .bim 的坐标列，32 位整数。单条染色体超过 2.1 Gb 时坐标会溢出成负数，PLINK 不报错，但位点位置全错，曼哈顿图会画得莫名其妙。
- 这里按实测数据交代一下，12 条染色体里第 3 号长 2,215,331,197 bp，已经超过 2^31，所以这个检查不是多余的。
- 有输出就说明这份 .bim 不能用，要回到上游把坐标或工具换成支持 64 位的。

## 亲缘矩阵

亲缘矩阵描述谁和谁像，用全基因组位点算出个体两两的相似度，也就是遗传关系矩阵（GRM），它在模型里充当随机效应的协方差结构，把家系结构吸收掉。

```bash
fastlmmc -bfileSim 06.gwas/fastlmm/mt160 -pheno 06.gwas/fastlmm/pheno_fastlmm.txt -simOut 06.gwas/fastlmm/mt160.sim -runGwastype NORUN -maxThreads 32 > 06.logs/fl3_kinship.log 2>&1
```

- `-bfileSim`，加 Sim 后缀才是只算相似度矩阵的模式。写成 `-bfile` 会当成跑关联，读不到结果表。
- `-simOut`，相似度矩阵的输出路径。
- `-runGwastype NORUN`，NORUN 表示只算矩阵、不做关联。大小写不敏感，写成 `-runGwasType` 也能跑。
- `-pheno`，表型文件，无表头，第一列和第二列是 FID 和 IID，后面是各个性状，顺序与 .fam 一致。
- `-maxThreads 32`，线程数。矩阵本身只有 160×160，跑得快，靠的是位点多；线程给多了也不会更快。
- fastlmmc 不在 PATH 里，它在 FastLMM 包的 site-packages 下面，形如 `<conda 环境>/lib/python2.7/site-packages/fastlmm/association/Fastlmm_autoselect/fastlmmc`，用之前先 `conda activate` 对应环境，或者把绝对路径写在命令里。

fastlmmc 跑完先确认它生成了 .sim 文件，空文件会让后面白跑：

```bash
[ -s 06.gwas/fastlmm/mt160.sim ] || { echo "ERROR: 未生成 mt160.sim"; exit 1; }
```

- `-s`，文件存在且非空。这一步的产物是 161 行，表头加 160 个样本。

文件存在还要看行数，表头加 160 个样本应当是 161 行：

```bash
wc -l 06.gwas/fastlmm/mt160.sim
```

- 矩阵算完先看对角线均值，个体自身的相似度应接近 1，群体内的两两相似度应明显高于群体间。热图上如果看不出任何块状结构，要么位点太少，要么样本本来就来自一个随机交配群体，此时亲缘校正不会改变结论。

## 群体结构

PCA 用固定效应扣掉连续的群体分层。取几个主成分不能凭感觉。

```bash
plink --bfile 06.gwas/fastlmm/mt160 --allow-extra-chr --pca 30 --memory 22000 --out 06.gwas/fastlmm/mt160.pca
```

- `--pca 30`，先算 30 个主成分。先多算，再拿着 twstats 的结果决定用前几个。

主成分算完用 twstats 判断该留几个，不要照搬别人的数字：

```bash
twstats -t twtable -i 06.gwas/fastlmm/mt160.pca.eigenval -o 06.gwas/fastlmm/mt160.pca.twtest
```

- `twstats`，EIGENSOFT 的 Tracy-Widom 检验，判断每个特征值是否显著偏离纯噪音。

数一下显著的主成分有几个，这个数就是要留的 PC 数：

```bash
awk 'NR>1 && NF>=5 && $5+0<0.05{n++} END{print n+0}' 06.gwas/fastlmm/mt160.pca.twtest
```

- `NR>1 && NF>=5 && $5+0<0.05`，跳过表头，第 5 列是 p 值，数出显著成分的个数。这批数据算出来是 18 个，后面的协变量一律取 PC1–PC18。
- 用的个数不能超过已算出的主成分数。只算了 30 个却写 31 或 40，会得到 31 这种离谱的个数，`covar.txt` 后面还会多出空列。
- 没装 twstats 时就直接取前 10 个，这个数字对结果影响不大，写清楚用了几个就行。
- 用的 PC 太少分层扣不干净，QQ 图整体上翘；用太多会把真实的关联信号一起当结构扣掉，真位点消失。

按上面定的个数把特征向量裁成协变量文件：

```bash
awk 'BEGIN{OFS="\t"} $1!~/^#/{ printf "%s\t%s", $1, $2; for(i=3;i<21;i++) printf "\t%s", $i; print "" }' 06.gwas/fastlmm/mt160.pca.eigenvec > 06.gwas/fastlmm/covar.txt
```

- `i=3; i<21`，plink 的 eigenvec 前两列是 FID 和 IID，第 3 列开始是 PC1，取到第 20 列正好 18 个主成分。换数据时这个上界要和上面 twstats 算出的个数一起改，改了一个忘另一个，协变量就会多一列少一列。
- 格式是 FID、IID，后面接各列协变量，不要有表头，这是 fastlmmc 的要求。

列数对一遍，fastlmmc 对着列位置读，多一列少一列都会错位：

```bash
awk -F'\t' '{print NF}' 06.gwas/fastlmm/covar.txt | sort -u
```

- 确认列数只有一个值，也就是 20。写错循环边界时会得到两个值，说明各行长度不一致。

## 关联分析

### plink2

plink2 这一路先用全部位点算亲缘矩阵：

```bash
plink2 --bfile 06.gwas/fastlmm/mt160 --make-rel square --out 06.gwas/fastlmm/grm --threads 16
```

- `--bfile`，读入 PLINK 二进制三件套。
- `--make-rel square`，输出方阵形式的遗传关系矩阵。方阵便于和 fastlmmc 的相似度矩阵交叉检查，两个矩阵的对角线应都接近 1，不一致的样本往往是基因型缺失率偏高的那几个。
- `--out`，输出前缀，矩阵文件由它拼出来。
- `--threads 16`，线程数。

再带上表型、协变量和亲缘矩阵跑关联：

```bash
plink2 --bfile 06.gwas/fastlmm/mt160 --pheno phenotype_191.phen --pheno-name DBH --covar 06.gwas/fastlmm/mt160.pca.eigenvec --covar-name PC1-PC18 --glm hide-covar --adjust --out 06.gwas/fastlmm/plink2.DBH --threads 16
```

- `--pheno-name DBH`，按名字指定性状，比按列号更不容易错。同一份表型文件里有多个性状时只改这一个参数。注意 plink2 读的就是带表头的原表型文件，与 fastlmmc 那份无表头副本不是同一个。
- `--covar-name PC1-PC18`，指定用哪些列作协变量，这里的 18 就是 twstats 算出的显著主成分数。
- `--glm hide-covar`，跑广义线性模型，hide-covar 表示输出结果里不显示协变量自身的效应，只留位点效应。
- `--adjust`，同时输出 Bonferroni 和 FDR 校正后的 p 值，不用事后另算。
- plink2 的 --glm 不带随机效应，亲缘校正不完整，这一条路线只能当快速交叉验证用，两个工具都在同一位点附近给出信号，才值得往下做。
- 14 个性状各跑一遍，与 fastlmmc 那边同一套写法。

### fastlmmc

一次只能算一个性状。下面以 DBH 为例，`-mpheno` 就写它在表型文件里的列号，14 个性状依次换成 1 到 14 各跑一遍，

```bash
fastlmmc -bfile 06.gwas/fastlmm/mt160 -sim 06.gwas/fastlmm/mt160.sim -pheno 06.gwas/fastlmm/pheno_fastlmm.txt -mpheno 2 -covar 06.gwas/fastlmm/covar.txt -maxThreads 16 -out 06.gwas/fastlmm/gwas_DBH.fastlmm.txt > 06.gwas/fastlmm/gwas_DBH.log 2>&1
```

- `-mpheno 2`，用表型文件里第 2 个性状，FID 和 IID 不计入列号。14 个性状的列号与前面对照表里的一致，PH 是 1，FL 是 14，换下一个性状只改这个数字和 `-out` 的名字。
- `-sim`，上一步算出的相似度矩阵，这是 LMM 随机效应的输入。
- `-covar` 要显式传上。协变量文件不存在时 fastlmmc 会静静地退化成不带协变量继续跑，不报错，看上去做了结构校正、实际没有，是这类流程里最难发现的一类错。
- `-out` 带上性状名，后面提结果、画图全按 `gwas_<性状>.fastlmm.txt` 这个命名展开，不写性状名就被后一个性状覆盖了。
- 跑完对一下日志，用了协变量的日志里会有相关字样，只看到关联结果而没有协变量的记录，就要回头查 `covar.txt`。
- 14 个性状各自跑一遍，输出和日志都带上性状名，否则后一个性状会把前一个的文件覆盖掉。

### GEMMA

不同 LMM 实现对亲缘矩阵的估计和优化方式不同，结果不一致的位点值得单独看。

```bash
plink --bfile 06.gwas/fastlmm/mt160 --keep samples/keep.txt --make-bed --out gemma/geno
```

- `--keep`，只保留表型和基因型都齐全的个体。

换成 GEMMA 再跑一遍，两个软件的假设不同，结果可以互相印证：

```bash
gemma -bfile gemma/geno -gk 2 -o kinship
```

- `-gk 2`，算中心化的相关矩阵，作为亲缘矩阵。

亲缘矩阵有了就跑关联，这一步输出所有位点的结果：

```bash
gemma -bfile gemma/geno -k output/kinship.cXX.txt -lmm 1 -c gemma/covar_pc5.txt -o DBH
```

- `-lmm 1`，Wald 检验，输出所有位点的结果。
- `-lmm 2`，似然比检验，更快，p 值略保守。位点很多时先用 2 扫一遍，对候选区间再用 1 精算。
- `-c`，协变量文件，GEMMA 的格式要求第一列是 1。这一列不能少，否则报错。

## 结果整理与出图

fastlmmc 的输出列名不统一，不同版本的 FastLMM 叫法不一样，所以加一个提取脚本把列对干净，后面绘图、筛显著位点都用它的输出。脚本按表头认列，位点名、染色体、位置、p 值的常见写法都认得：

```python
#!/usr/bin/env python3
"""整理 fastlmmc 的输出表。默认输出 SNP CHR BP P, --cmplot 只输出 CHR BP P"""
import argparse
import sys


def key(h):
    return h.strip().lstrip("#").lower().replace("-", "_")


def find(header, keys):
    for i, h in enumerate(header):
        if any(k in key(h) for k in keys):
            return i
    return None


def is_num(x):
    try:
        float(x)
        return True
    except ValueError:
        return False


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("table")
    ap.add_argument("--cols", help="手动指定四列, 从 1 开始, 逗号分隔")
    ap.add_argument("--cmplot", action="store_true", help="只输出 CHR BP P")
    args = ap.parse_args()

    rows = [l.split() for l in open(args.table) if l.strip()]
    has_header = not is_num(rows[0][-1])

    if args.cols:
        cols = [int(c) - 1 for c in args.cols.split(",")]
    elif has_header:
        p = find(rows[0], ("pval", "p_value", "pvalue"))
        if p is None:
            p = next((i for i, h in enumerate(rows[0]) if key(h) == "p"), None)
        cols = [find(rows[0], ("snp", "marker", "rs")), find(rows[0], ("chr",)),
                find(rows[0], ("pos", "bp")), p]
        if any(c is None for c in cols):
            cols = [0, 1, 2, len(rows[0]) - 1]
            sys.stderr.write("列名认不出, 按第 1、2、3 列和最后一列处理\n")
    else:
        cols = [0, 1, 2, len(rows[0]) - 1]

    data = rows[1:] if has_header else rows
    print("CHR\tBP\tP" if args.cmplot else "SNP\tCHR\tBP\tP")
    for r in data:
        v = [r[c] for c in cols]
        print("\t".join([v[1], v[2], v[3]]) if args.cmplot else "\t".join(v))


if __name__ == "__main__":
    main()
```

每个性状跑两遍，一遍给下游筛显著位点，一遍给 CMplot：

```bash
for f in 06.gwas/fastlmm/gwas_*.fastlmm.txt; do
  t=$(basename "$f"); t=${t#gwas_}; t=${t%.fastlmm.txt}
  python3 scripts/fastlmm_extract.py "$f" > 06.gwas/fastlmm/result/$t.draw
  python3 scripts/fastlmm_extract.py "$f" --cmplot > 06.gwas/fastlmm/result/$t.cmplot.tsv
  awk 'BEGIN{OFS="\t"} NR==1{print; next} $4+0<5e-8' 06.gwas/fastlmm/result/$t.draw > 06.gwas/fastlmm/result/$t.sig.txt
  echo "$t 位点=$(wc -l < 06.gwas/fastlmm/result/$t.draw)  显著=$(($(wc -l < 06.gwas/fastlmm/result/$t.sig.txt)-1))"
done
```

- 认不出列名时用 `--cols` 手工指定四个列号（从 1 开始），没有表头时按第 1、2、3 列加最后一列处理。
- 默认输出四列 `SNP CHR BP P`，带表头，存成 `.draw`；`--cmplot` 模式只输出 `CHR BP P` 三列，直接给 CMplot 用。
- `NR==1{print; next}`，先打印表头再筛。丢掉表头的话下游 `read.table(header=TRUE)` 会把第一个位点当列名。
- `$4+0<5e-8`，这里用人类阈值只是先把候选位点挑出来看一眼，正式报告要按前面说的三种标准另算，并做连锁不平衡剪枝。
- `t=${t#gwas_}; t=${t%.fastlmm.txt}`，从文件名里剥出性状名。`${var#前缀}` 去头部，`${var%后缀}` 去尾部，比 `basename` 加 `cut` 稳，不会把性状名里可能出现的下划线切掉。

绘图用 CMplot，一个性状一张曼哈顿图加一张 QQ 图，

```r
suppressMessages(library(CMplot))
dir.create("06.gwas/fastlmm/plot", recursive = TRUE, showWarnings = FALSE)
old_wd <- getwd()
setwd("06.gwas/fastlmm/plot")

for (f in list.files(file.path(old_wd, "06.gwas/fastlmm/result"), pattern = "\\.draw$", full.names = TRUE)) {
  trait <- sub("\\.draw$", "", basename(f))
  d <- read.table(f, header = TRUE, stringsAsFactors = FALSE)
  d <- data.frame(SNP = d[[1]], Chromosome = d[[2]], Position = as.numeric(d[[3]]),
                  P = as.numeric(d[[4]]))
  d <- d[is.finite(d$P) & d$P > 0, ]
  cat(sprintf("%s: %d 个位点\n", trait, nrow(d)))
  CMplot(d, plot.type = "m", LOG10 = TRUE,
         threshold = c(5e-8, 1e-5), threshold.lty = c(1, 2), threshold.lwd = c(1, 1),
         threshold.col = c("red", "blue"),
         amplify = TRUE, signal.cex = 1.2, signal.pch = 19, signal.col = "red",
         col = c("grey30", "grey60"), cex = 0.4,
         file = "pdf", file.name = paste0(trait, ".Manhattan"),
         dpi = 300, file.output = TRUE, verbose = FALSE, width = 14, height = 5)
  CMplot(d, plot.type = "q", LOG10 = TRUE, conf.int = TRUE, conf.int.col = "grey60",
         file = "pdf", file.name = paste0(trait, ".QQ"),
         dpi = 300, file.output = TRUE, verbose = FALSE, width = 6, height = 6)
}
setwd(old_wd)
```

- `setwd("06.gwas/fastlmm/plot")` 不能省，CMplot 4.5.1 没有 `outpath` 参数，图直接写到当前目录。不切目录时图片会落在脚本所在目录，和结果目录混在一起。跑完再 `setwd(old_wd)` 切回去，也方便以后把这段代码包进函数。
- `d[[1]]` 到 `d[[4]]` 按列序号取而不是按列名，`.draw` 的列名可能是 `SNP/CHR/BP/P`，也可能带别的写法。取完统一重命名成 CMplot 要求的 `SNP Chromosome Position P`，列名可以改，顺序不能变。
- `d[is.finite(d$P) & d$P > 0, ]`，去掉 p 值为 0、NA、Inf 的行。p 值为 0 时 -log10 会变成无穷大，整张曼哈顿图的纵轴会被拉到看不见别的点。
- `pattern = "\\.draw$"`，只读提取脚本产的四列表，不碰同目录里的 `.cmplot.tsv` 和 `.sig.txt`。
- `threshold = c(5e-8, 1e-5)` 配 `threshold.lty = c(1, 2)`，画两条参考线，实线是基因组显著、虚线是提示水平。参考线不是判据本身，只用来对照。
- `amplify = TRUE` 与 `signal.col = "red"`，超过阈值的点放大并标红。真正的信号不会多，点太密说明阈值太松或者模型没扣干净。
- `width = 14, height = 5`，曼哈顿图横长、QQ 图近正方形。CMplot 默认尺寸下 12 条染色体的标签会重叠。

- QQ 图是判断这次 GWAS 能不能信的第一张图。点贴着对角线，末端轻微上翘是正常的；整条线整体抬起，也就是 QQ 膨胀，说明分层没扣干净，要回过去加主成分或检查亲缘矩阵；点整体落在对角线下方说明模型过度校正，主成分用太多，或者亲缘矩阵里混进了与表型相关的信息。
- 显著性阈值不能只有 5e-8 一个。这个值是人类的经验值，植物群体连锁不平衡衰减快、位点间独立性强，对植物往往过严。同时报三种标准，Bonferroni，用 0.05 除以有效独立位点数，有效独立位点数就是连锁不平衡剪枝之后剩下的位点数，比原始位点数少一两个数量级，用它算比用总位点数合理；FDR；以及 5e-8。
- 显著位点要用连锁不平衡合并成区间再报，孤立的一个显著位点在大位点集里很可能是假阳性。
- 多个性状都出图之后并排看，同一位点能同时解释两个相关性状（比如胸径和树高），比只在一个性状上显著更可信。
